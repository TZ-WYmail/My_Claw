# 阶段 4：前端信息架构与命名对齐计划

更新时间：2026-06-12  
阶段目标：让前端的页面、命名、导航和真实业务模型重新对齐

## 1. 本阶段目标

本阶段不是重做 UI，而是解决以下问题：

1. 页面命名与业务语义失配
2. feature 边界与后端模块边界不一致
3. 导航结构仍然反映旧系统心智
4. 页面和 hook 的归属关系不够清晰

## 2. 范围

包含：

- 页面职责梳理
- 页面命名清理计划
- feature 分组重排
- 导航信息架构调整计划
- 前后端模块映射对齐

不包含：

- 实际页面改版
- 组件重写
- CSS 重构
- 路由实现替换

## 3. 待完成任务

### 任务 A：重画前端 feature 版图

要把前端按 feature 重新理解，而不是只按页面文件分布理解。

建议至少分为：

- productivity feature
- ai/agent feature
- mail feature
- platform feature

### 任务 B：梳理页面职责与真实业务语义

为主要页面建立一张对照表：

- 文件名
- 当前导航名
- 实际业务职责
- 建议归属模块
- 是否存在命名失真

### 任务 C：识别高优先级命名失真

重点识别：

- 页面名与业务内容不一致
- 组件名继承旧语义
- hook 名称无法准确反映归属

### 任务 D：重整导航信息架构

明确以下问题：

- 顶层导航按什么组织
- 哪些功能是一级入口
- 哪些应该下沉为二级入口
- 哪些能力不该直接暴露为顶层主导航

### 任务 E：建立前后端模块映射表

为每个主要前端 feature 标注：

- 对应后端模块
- 依赖的核心 API 组
- 是否跨模块拼接状态

### 任务 F：识别前端状态过载页面

重点标记：

- 页面承担过多业务编排
- 页面命名已不适配职责
- 页面内部状态过度膨胀

## 4. 依赖关系

本阶段依赖：

- 阶段 1 的领域边界结果
- 阶段 2 的应用层规划

本阶段输出将直接支持：

- 前端目录重整
- 页面与 hook 归位
- 后续 UI 重构

## 5. 风险与阻塞点

### 风险 1：只改名字，不改信息架构

这样会让问题延后，但不会消失。

### 风险 2：试图在本阶段重做视觉设计

本阶段是结构对齐，不是视觉翻新。

### 风险 3：前端 feature 与后端模块强行一一对应

要尽量对齐，但不能机械映射。某些前端页面天然是跨模块工作台。

## 6. 产出物

本阶段产出应包括：

1. 前端 feature 版图
2. 页面职责对照表
3. 命名失真清单
4. 导航结构调整草案
5. 前后端模块映射表
6. 高状态复杂度页面清单

## 7. 完成标准

满足以下条件，才算本阶段完成：

1. 主要页面的真实职责已被明确
2. 高优先级命名失真已被识别
3. 顶层导航结构有了统一设计原则
4. 前端 feature 与后端模块基本可对齐

## 8. 本阶段不做的事情

本阶段明确不做：

- 页面重写
- 样式系统翻新
- 新交互方案设计
- 大规模组件迁移
