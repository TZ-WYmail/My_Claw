# 阶段 5：兼容层收缩与落地验证计划

更新时间：2026-06-12  
阶段目标：在不破坏现有系统可用性的前提下，给重整后的结构建立退出路径与验证闭环

## 1. 本阶段目标

当前系统里存在较多兼容层、聚合层和历史命名残留。  
本阶段目标是：

1. 明确哪些兼容层暂时保留
2. 明确哪些兼容层进入淘汰计划
3. 明确每次重整后的验证方式
4. 明确阶段性交付与回滚边界

## 2. 范围

包含：

- 兼容层分类
- 保留/收缩/淘汰判定标准
- 阶段性验证清单
- 风险控制清单
- 发布与回滚建议

不包含：

- 具体回归测试实现
- 具体兼容代码删除
- 具体发布脚本调整

## 3. 待完成任务

### 任务 A：建立兼容层清单

需要识别的兼容层类型包括：

- 命名兼容层
- 调用路径兼容层
- API 兼容层
- 数据结构兼容层
- 页面语义兼容层

### 任务 B：定义兼容层判定标准

每个兼容层都要回答：

- 它解决什么历史问题
- 当前是否仍有活跃依赖
- 是否已经有正式替代路径
- 是否应该继续暴露

### 任务 C：建立保留与淘汰优先级

建议分类：

1. 必须短期保留
2. 可进入观察期
3. 可计划淘汰

### 任务 D：建立阶段验证清单

每个阶段完成后，需要验证：

- 主路径是否仍可用
- 跨模块关键用例是否可用
- AI 核心链路是否可用
- 邮件核心链路是否可用
- 前端关键导航与主页面是否可用

### 任务 E：建立风险控制清单

重点关注：

- 跨域调用中断
- 状态丢失
- 历史入口失效
- 前端页面引用断裂
- 自动化逻辑误切断

### 任务 F：建立阶段性交付规则

明确以下问题：

- 哪些改动可以独立交付
- 哪些改动必须成组交付
- 哪些阶段需要冻结新功能
- 哪些阶段允许并行推进

## 4. 依赖关系

本阶段依赖：

- 阶段 1 的兼容层识别结果
- 阶段 2 的用例收口规划
- 阶段 3 的状态治理规划
- 阶段 4 的前端对齐规划

## 5. 风险与阻塞点

### 风险 1：兼容层无限延期

如果没有明确退出条件，兼容层会永久存在。

### 风险 2：为了收缩兼容层破坏主路径

兼容层收缩必须服从主路径稳定性。

### 风险 3：验证只测单点，不测完整流程

必须按关键业务流验证，而不是只测单个接口。

## 6. 产出物

本阶段产出应包括：

1. 兼容层总清单
2. 保留/观察/淘汰分类表
3. 阶段验证清单
4. 风险控制表
5. 阶段性交付规则
6. 回滚关注点清单

## 7. 完成标准

满足以下条件，才算本阶段完成：

1. 兼容层不再是模糊概念，而是有清单和分类
2. 每次结构调整都有明确验证闭环
3. 主要风险点已被事先记录
4. 后续删兼容层不再靠临场判断

## 8. 本阶段不做的事情

本阶段明确不做：

- 一次性删除全部兼容代码
- 大规模回归测试脚本编写
- 自动发布流程重建
- 新监控系统引入
